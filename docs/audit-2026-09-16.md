# Auditoría técnica — 2026-09-16

## Resultado

La aplicación compila en producción, pasa ESLint sin advertencias y pasa la
comprobación estricta de TypeScript. La auditoría de dependencias de producción
quedó en **0 vulnerabilidades críticas** y **2 altas** (ambas bloqueadas por la
versión actual de BlockNote; ver pendientes).

## Mejoras aplicadas

### Seguridad y dependencias

- Next.js actualizado de 16.2.0 a 16.3.5.
- NextAuth actualizado de 5.0.0-beta.30 a 5.0.0-beta.32.
- `@auth/prisma-adapter` actualizado a 2.11.3 y `@auth/core` fijado en la
  versión parcheada 0.41.3.
- Dependencias transitivas vulnerables actualizadas con overrides de parche
  (`hono`, `fast-uri`, `mysql2`, `nanoid`, `js-yaml`, `browserslist`, etc.).
- `shadcn` movido a `devDependencies`: es una herramienta de desarrollo, no una
  dependencia necesaria en producción.
- Límite de payload restaurado de 20 MB a 5 MB para reducir superficie de abuso.
- Emails de login/registro normalizados y validados; las contraseñas recibidas
  tienen límites explícitos.

### Integridad de sesiones Solarium

- Nuevo schema Zod compartido para validar en servidor IDs, duración, título y
  métricas de cierre.
- IDs duplicados de material se eliminan antes de consultar o crear la sesión.
- Los endpoints de completar y abandonar rechazan payloads inválidos.
- El heartbeat se envía inmediatamente al entrar y después cada 45 segundos.
- El cierre/recarga real de la pestaña vuelve a persistir el abandono mediante
  `navigator.sendBeacon`; el endpoint existía, pero no estaba conectado.

### Calidad y desarrollo

- Corregidas las 11 advertencias que impedían que el lint terminase con éxito.
- El botón de login muestra estado pendiente y evita envíos repetidos.
- El script que libera el puerto 3000 ahora funciona en Windows, macOS y Linux.
- La versión mínima de Node se alinea con el README (`>=20.19`).
- `NODE_ENV` queda declarado para el cacheado correcto de Turborepo.

## Pendientes recomendados

1. **Actualizar BlockNote como bloque**. Las 2 vulnerabilidades altas restantes
   están en `@tiptap/core` y `deepmerge-ts`, transitivas de BlockNote 0.49. Forzar
   solo Tiptap 3.30.5 rompe el build por incompatibilidad con
   `@tiptap/react@3.22.5`; debe actualizarse y probarse el conjunto BlockNote
   (`core`, `react`, `mantine`) en una tarea dedicada, especialmente pegado,
   tablas y resaltado de código.
2. **Añadir pruebas automatizadas**. No existe suite. Prioridad: servicios de
   Solarium, autorización/ownership de repositories y schemas de acciones/API.
3. **Rate limiting distribuido**. Login, registro, feedback y mutaciones siguen
   sin límites. Para despliegue serverless conviene Redis/Upstash o equivalente,
   no un contador en memoria.
4. **Observabilidad**. Añadir monitorización de errores y métricas mínimas de
   creación, finalización y abandono de sesiones.
5. **Separar staging y producción**. `dev` continúa actuando como rama de
   producción según la documentación del proyecto.
